Giai đoạn 5 - Hoàn thành

Exponential Backoff Retry & Dead Letter Queue (Retry Service - Port 3003)

Đăng ký lắng nghe lỗi gửi tin, tính toán thời gian chờ lũy thừa và chuyển tiếp message hết hạn vào DLQ.

Học phần: Lập trình API

Hệ thống quản lý Facebook Page

Các đầu việc đã thực hiện

  • Thiết lập Retry Service độc lập Đã tách retry thành service chạy độc lập tại cổng 3003 (services/retry-service/), giảm tải hoàn toàn cho Backend API chính.
  • Cơ chế Exponential Backoff Khi nhận message từ topic send_failed, service trì hoãn bất đồng bộ (async sleep) thời gian lũy thừa tăng dần theo công thức wait = 1s * 2^retry_count trước khi thử lại:
    • Thử lại lần 1: Chờ 1 giây
    • Thử lại lần 2: Chờ 2 giây
    • Thử lại lần 3: Chờ 4 giây
    • Thử lại lần 4: Chờ 8 giây
    • Thử lại lần 5: Chờ 16 giây
  • Chuyển tiếp Dead Letter Queue (DLQ) Khi đạt ngưỡng tối đa N lần (mặc định N = 5), thay vì retry vô hạn gây nghẽn, service chuyển tiếp message lỗi sang topic dead_letter, kết thúc chu kỳ retry. Điều này kích hoạt cảnh báo Prometheus Alertmanager gửi về Slack để quản trị viên can thiệp thủ công.

🔄 Sơ đồ luồng xử lý lỗi và Retry

Backend API → Gửi Facebook thất bại → Publish topic "send_failed"
↓
Retry Service → Nhận message → Đọc retry_count
↓ (Nếu retry_count < 5)
Exponential Sleep → Tăng retry_count → Publish topic "send_retry" → Backend API nhận & thử lại
↓ (Nếu retry_count >= 5)
Max Limit Reached → Publish topic "dead_letter" → Prometheus Alert → Slack

Cấu hình số lần Retry

MAX_RETRY trong .env

Mặc định hệ thống sẽ thử lại tối đa 5 lần. Bạn có thể thay đổi số lần thử lại bằng cách chỉnh sửa file services/retry-service/.env:

MAX_RETRY=3
